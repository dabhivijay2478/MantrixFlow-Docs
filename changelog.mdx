## 2026-04-27 — Postgres-to-Postgres live release

- **Postgres-to-Postgres pipelines** are now live. Read from any PostgreSQL source (Neon, RDS, Aurora, Supabase, Cloud SQL, Azure, Aiven) and write to any PostgreSQL destination.
- Full coverage of all official PostgreSQL data types: numeric, character, datetime, boolean, binary, network, JSON, UUID, XML, bit string, arrays, geometric, range, text search, composite, and enum.
- Cross-type widening support: `CHAR`/`VARCHAR` → `TEXT`, `SMALLINT` → `BIGINT`, `REAL` → `DOUBLE PRECISION`, `DATE` → `TIMESTAMPTZ`, and more.
- Upsert write mode available for all P2P pipelines. Rows are matched by primary key and inserted or updated atomically.
- Dynamic schema naming for test and E2E runs — schemas use unique suffixes to avoid conflicts across runs.
- SQL transform editor supports all PostgreSQL cast syntax, JSONB operators, aggregation, filtering, and derived columns.
- Added documentation: [Postgres-to-Postgres guide](/example/pipelines/postgres-to-postgres), [P2P SQL examples](/example/pipelines/postgres-to-postgres-examples), and [Data type compatibility](/pipelines/data-type-compatibility).

## 2026-01-31 — Incremental sync and upsert

- Incremental sync mode released for PostgreSQL, MySQL, and MariaDB sources. Choose a cursor column (`updated_at`, `id`, etc.) and MantrixFlow tracks the high-water mark automatically.
- Upsert write mode released as the production destination write mode. Matches rows by primary key and performs insert-or-update in one operation.
- Sync state page added to the pipeline builder. View and reset the stored cursor or CDC checkpoint for each pipeline.
- `TIMESTAMPTZ` cursor columns now handle timezone-aware comparisons correctly across providers.

## 2025-10-01 — Project start

MantrixFlow started with a single goal: make data pipelines simple enough that any developer can build and run one in minutes, without managing infrastructure.

- Core pipeline model defined: source connection → optional transform → destination connection.
- ELT server architecture chosen: DuckDB-staged extraction, dlt-based loading, async callback to the Go API.
- Go API (Fiber) and Python ELT server (FastAPI + uvicorn) set up as the two backend services.
- PostgreSQL chosen as the first source and destination type for the initial live release.
- Supabase chosen as the primary database for the MantrixFlow platform itself (auth, org, pipeline metadata).
- MantrixFlow cloud at [cloud.mantrixflow.com](https://cloud.mantrixflow.com) set as the deployment target.
