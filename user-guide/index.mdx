This guide is written against the current workspace behavior, not an abstract ETL concept model. The page names, routes, and actions below match the product you see in the app.

## The end-to-end flow this guide follows

1. Make sure you are in the right organization.
2. Create and test source and destination connections.
3. Create a pipeline shell from **Data Pipelines**.
4. Finish the real configuration in the builder.
5. Run manually, validate the destination, and only then add a schedule.
6. Use **Run History** and **Activity Log** when something breaks.

## Product terminology to keep straight

| Concept | Where it lives in the app |
| --- | --- |
| Source and destination credentials | **Connections** (`/workspace/connections`) |
| Pipeline shell creation | **Data Pipelines** (`/workspace/data-pipelines/new`) |
| Table selection, transforms, destination settings | Builder canvas (`/workspace/data-pipelines/[id]/builder`) |
| Operational history for one pipeline | Pipeline detail page |
| Org-wide operational events | **Activity Log** (`/workspace/activity`) |
| Access and roles | **Team** and **Settings** |
