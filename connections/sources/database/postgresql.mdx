PostgreSQL is the most complete database source in the current app. It supports table discovery, transform preview, incremental sync, and the in-product CDC setup flow.

## Current connection form

The current **PostgreSQL** source form asks for:

- `Connection Name`
- `Host`
- `Port`
- `Database`
- `Username`
- `Password`
- `Schema`
- `SSL Mode`

- `Port` defaults to `5432`.
- `Schema` defaults to `public`.
- `SSL Mode` options are `disable`, `allow`, `prefer`, `require`, `verify-ca`, and `verify-full`.

## Good first use cases

- replicate operational app tables into a reporting database
- start with incremental sync on `updated_at` and move selected tables to CDC later
- validate one high-value business table before broadening the rollout

## Before you connect

- Create a dedicated read-only user with schema and table access.
- Confirm the host, database, and schema you want to read first.
- Pick one table to validate first, usually `public.orders` or `public.customers`.

## Step by step

1. Open **Connections** and click **+ New Connection**.
2. Keep the role set to **Source** and choose **PostgreSQL**.
3. Fill the form with real values, for example:
   - `Connection Name`: `Neon Production`
   - `Host`: `ep-lighthouse-prod-123456.us-east-2.aws.neon.tech`
   - `Port`: `5432`
   - `Database`: `app`
   - `Username`: `mf_readonly`
   - `Schema`: `public`
   - `SSL Mode`: `require`
4. Click **Test Connection**. Save the connection only after the test succeeds.
5. Create a pipeline, pick the first table in **Source Configuration**, and run one manual sync before enabling a schedule.

## Good first tables

- `public.orders`
- `public.customers`
- `public.order_items`

## Real-world example

Lighthouse Commerce copies `public.orders` and `public.order_items` from Neon into an analytics PostgreSQL destination. The team starts with incremental sync on `updated_at` and later moves `orders` to CDC when refunds and deletes need faster visibility.

## Troubleshooting

- If table discovery is empty, re-check `USAGE` on the schema and `SELECT` on the tables.
- If the connection test fails with a TLS message, keep `SSL Mode` on `require` unless your DBA gives you a different value.
- If preview works but later runs fail, verify that the selected source table still exists and the saved connection still passes testing.

If you need log-based replication, save the connection first and then use [CDC setup for PostgreSQL](/sync-reference/cdc-postgresql).
