MantrixFlow uses different transform types depending on the pipeline source:

| Pipeline type | Transform language | Editor |
| --- | --- | --- |
| PostgreSQL-to-PostgreSQL | SQL `SELECT` statement | SQL editor in the Transform panel |
| SaaS sources (Shopify, Stripe, HubSpot, GitHub, Notion) | Python `transform(record)` function | Python editor in the Transform panel |

## SQL transforms (PostgreSQL-to-PostgreSQL)

Write a `SELECT` statement using `{{ source }}` as the table reference. MantrixFlow replaces it with the actual source stream at run time.

```sql
SELECT
  id,
  LOWER(email)                AS email,
  first_name || ' ' || last_name AS full_name,
  amount_cents::NUMERIC / 100  AS amount_usd,
  created_at::TIMESTAMPTZ     AS created_at
FROM {{ source }}
WHERE is_deleted = false
```

SQL transforms support all PostgreSQL syntax: casts, filters, derived columns, aggregations, JSONB operators, and cross-type widening. See [P2P examples](/pipelines/postgres-to-postgres) for a full pattern library.

## Python transforms (SaaS sources)

Write a function that accepts one record and returns a shaped record or `None` to drop it.

```python
def transform(record):
    return {
        "id": record.get("id"),
        "status": (record.get("status") or "").lower(),
        "amount": (record.get("amount_due") or 0) / 100,
    }
```

The function should:
- return a `dict` when the record should continue
- return `None` to drop the record
- avoid filesystem, network, or environment access

## What the Transform panel includes

- branch label and source-table selector
- SQL editor (P2P pipelines) or Python editor (SaaS pipelines)
- source-specific example packs for PostgreSQL, Stripe, Shopify, HubSpot, Notion, and GitHub
- **Preview** using up to 10 live source rows
- **Save** action
- a separate **Filter** node with Python-expression and SQL-`WHERE` modes

## Preview every meaningful change

Use preview whenever you:

- change field names
- cast types
- filter rows
- touch nested JSON structures
- prepare a destination table that other teams will query immediately

## Recommended workflow

1. Select the source table or resource first.
2. Start with the pass-through script.
3. Load an example only if it matches the current payload shape closely.
4. Make one change at a time.
5. Run **Preview with sample data** after each meaningful edit.
6. Save the script.
7. Validate the destination preview and then run the pipeline manually.

Read the detailed guides in the [Transformations](/transformations/overview) section for the current editor, filter, and preview behavior.
