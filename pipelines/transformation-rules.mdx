The current builder centers transformation work around a branch-scoped Python `transform(record)` function. Renaming, casting, derived columns, null handling, and nested-payload cleanup are implemented inside that script rather than through separate point-and-click mapping screens.

## What the current implementation includes

- a **Transform** panel with a branch label, source-table selector, Python editor, example loader, preview button, and **Save Script**
- source-specific example packs for PostgreSQL, MySQL, Stripe, Shopify, HubSpot, Notion, and GitHub
- fallback default SQL examples for source types without their own example pack
- sample-data preview for the current transform, using up to 10 source rows in the builder flow
- a separate **Filter** node with Python-expression and SQL-`WHERE` modes
- destination-side schema preview after the destination is saved

## What is not the supported workflow

- a standalone visual rename screen
- a dedicated cast wizard
- a separate null-fill product surface
- visual mapping docs as the main production path
- a user-facing toggle for skipping transform errors; current saved scripts default to failing the run on transform errors

## What a script must do

Use a Python function with this shape:

```python
def transform(record):
    return record
```

The function should:

- return a `dict` when the record should continue
- return `None` when the record should be dropped
- stay focused on record shaping rather than filesystem, network, or environment access

## Preview every meaningful change

Use preview whenever you:

- change field names
- cast types
- filter rows
- touch nested JSON structures
- prepare a destination table that other teams will query immediately

## Recommended workflow

1. Select the source table or resource first.
2. Start with the pass-through script.
3. Load an example only if it matches the current payload shape closely.
4. Make one change at a time.
5. Run **Preview with sample data** after each meaningful edit.
6. Save the script.
7. Validate the destination preview and then run the pipeline manually.
