title: Sync modes
description: Choose between full sync and incremental sync based on source behavior, table size, and freshness requirements.
---

Sync mode decides how MantrixFlow reads data from the source. The right choice depends on table size, resource behavior, and freshness requirements.

## Quick comparison

| Mode | Status | Best for | Main tradeoff |
| --- | --- | --- | --- |
| Full sync | **Available** | Any table — recommended for first runs and correctness validation | Re-reads everything each run |
| Incremental sync | **Beta** | Growing tables with a reliable update field like `updated_at` | Depends on correct cursor behavior; not fully production-tested |

## Full sync

Use full sync when the dataset is modest or the source does not expose a good cursor. Recommended for all first runs, correctness checks, and smaller reference tables. This is the safest mode and the one to start with.

## Incremental sync

<Warning>
  Incremental sync is in **beta** and has not been fully tested across all source types. Use full sync for production workloads until this notice is removed.
</Warning>

Use incremental sync when records have a trustworthy field such as `updated_at`, `modified_at`, or a monotonic ID. See [Incremental sync](/sync-reference/incremental-sync) for configuration steps and limitations.

## How to choose

- **Start with full sync** for all new pipelines. Validate that data looks correct end-to-end.
- Consider **incremental sync** only once full sync is confirmed working and table volume makes full re-reads expensive.

## Companion destination decision

Read mode and write mode are separate concerns. The only available destination write mode today is **Upsert**.
