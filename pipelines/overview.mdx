A MantrixFlow pipeline is the operational definition of how data should move from one source connection into one or more destinations.

## The current lifecycle

1. Create a pipeline shell from **Data Pipelines**.
2. Open the builder canvas.
3. Select the source table or SaaS resource.
4. Add transforms or filters if needed.
5. Configure the destination connection, schema, table, and schedule.
6. Save, run manually, and validate the result.

## The parts of a pipeline

- **Pipeline shell**: name plus source connection
- **Source configuration**: the concrete table or resource to sync
- **Transform branch**: optional Python logic that reshapes each record
- **Destination configuration**: connection, schema, table, write mode, preview, and schedule
- **Run history**: the operational record of every execution
- **Sync state**: the stored cursor or CDC checkpoint for incremental and CDC flows

## What is true in the live builder today

- Stream selection happens in **Source Configuration**.
- The transform editor uses Python and supports sample-data preview.
- The destination panel handles validation, preview, and scheduling.
- **Upsert** is the supported production write mode documented here.

## Typical production patterns

- one PostgreSQL table feeding one PostgreSQL reporting table
- one Shopify or Stripe resource feeding one SQL destination table
- one source stream branching to PostgreSQL for analytics and MySQL for internal operations
- a PostgreSQL source starting with incremental sync and moving to CDC later
