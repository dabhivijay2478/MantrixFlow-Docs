---
title: Sync state
description: What MantrixFlow tracks for incremental and CDC pipelines, how operators should think about it, and where it shows up in the current workflow.
---

Sync state is the checkpoint MantrixFlow uses to decide where the next run should resume. It matters most for incremental and CDC pipelines.

## What sync state contains

For incremental sync, the state typically represents the latest successful cursor value. For CDC, it represents the latest successful replication checkpoint used by the pipeline service.

## What operators see today

In the standard workspace flow, operators mostly experience sync state indirectly through:

- successful incremental runs only pulling newer rows
- CDC pipelines resuming from the last processed log position
- run history showing whether the pipeline is progressing normally

The state itself is not exposed as a standard self-serve reset screen in the current product.

## Practical example

Suppose Lighthouse Commerce runs an incremental sync on `orders.updated_at` every 15 minutes. After a successful run at 10:00, MantrixFlow stores the latest processed high-water mark. The 10:15 run uses that checkpoint so it reads only rows newer than the prior successful state.

## Recommended operator workflow

1. Check **Run History** first.
2. Confirm whether the issue is source-side, transform-side, or destination-side.
3. If the cursor or CDC assumptions changed, treat that as an operational recovery task instead of a casual reset.
4. Re-run manually before restoring the schedule.
